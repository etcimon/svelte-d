# wasm-eh and throwBoundary

The default engine configuration is `application` / `ldc-master`. That means `--wasm-enable-eh`, `-mattr=+exception-handling`, `--foptimize-nothrow=false`, and a post-build copy of `svelte-engine-raw.wasm` to `svelte-engine.wasm`. There is no Binaryen `--asyncify` on this path. Navbar-style `try/catch` and printed `throwBoundary` need `try_table` / `catch_ref`. Host 1.42, and 1.43-without-those-flags, emit a throw that JS `captureException` turns into an abort. The module links. The first catch dies.

`--foptimize-nothrow` is the LDC 1.43 default on Windows and wasm, because it makes an unrelated LLVM bug less likely. It also deletes landing pads inside `nothrow` functions. Almost every printed struct is `nothrow:`. Without `--foptimize-nothrow=false`, D `catch` vanishes and you will debug a “working” binary that never enters the `catch`. The engine’s `dub.sdl` already passes the flag. A hand-built wasm that omits it is not this cell.

`throwBoundary` is same-function `try` / `throw` / `catch` on the same struct as `trip()`, then `failBoundary`. Personality is first-catch-type only. An exception that crosses a function boundary is an abort. See [await / boundary](../language/await-boundary).

Do not compose this module with Binaryen 132 Flatten `--asyncify`. Do not print `.await` on this cell. A function that both catches and awaits is asking those two worlds to share a frame. Named `ldc-1.42` / `ldc-1.36` configs remain for asyncify work; they are not the default, and they do not do D `catch`.
