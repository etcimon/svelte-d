# CLI

`bunx svelte-d <cmd>` forwards to the native executable, except for `setup`, which the bun bin runs in TypeScript so it works before that executable exists. Dest flags (`--dest`, `--ws`) override `svelte-d.config.ts`. Without them, dest is the configured `workspace` or `<project>/svelte-engine-ws`.

`setup` finds or downloads LDC 1.43 and `dub add-local`s libwasm / vibe.0 when checkouts exist. `drop-ws` copies the packaged engine; `--force` refreshes sources and keeps `node_modules` / `.dub`. `parse` is one file, Pegged plus libdparse. `scan` lists kit files in a workspace. `compile` drops if needed, ingests `--project` (or cwd if it has `src/routes`), prints IR, and writes `fallthrough.json` / the debug map. `--only FILE` reprints one kit source for watch / HMR.

`map` with a kit path prints one JSON object; `map --ws DIR` writes `fallthrough.json` for the whole tree. `bootstrap` writes and checks the engine-integration contract. `kit-routes` lists pattern, kit rel, and `src-d`. `lodash` lists `libwasm.lodash` methods. `wasm` is the wasm-eh cell (`--probes` runs `run-probes.mjs`; `--force` rebuilds). `host` is `dub build` in `ws/webserver`. `version` prints `1`.

```
svelte-d setup
svelte-d drop-ws [--dest DIR] [--force]
svelte-d parse <file.svelte|+page.server.d>
svelte-d scan [--ws DIR]
svelte-d compile [--ws DIR] [--project DIR] [--only FILE]
svelte-d map <src/routes/+page.svelte>
svelte-d map --ws DIR
svelte-d bootstrap [--ws DIR]
svelte-d kit-routes [--ws DIR]
svelte-d lodash
svelte-d wasm [--ws DIR] [--probes] [--force]
svelte-d host [--ws DIR]
svelte-d version
```
